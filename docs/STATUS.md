# Status

## Current TTP and runtime state

- The external in-HAL route has now completed a real RD → APSS → WR buffer while retaining the original signed DSP. An accepted R3/HQ44.1 buffer changed its packet TTP from 191,000 to 341,000 µs, with the matching WR_DONE acknowledgement. This confirms one +150 ms packet transformation; it does **not** establish continuous forwarding, receiver timing or heard audio.
- Continuous forwarding remains under investigation. The original relay stalls on the next, timing-free supplemental packet; both +1 ms and a separately identified zero-change diagnostic reproduce it. A default-disabled RAW-island topology first advanced to four WR completions while losing initial PCM-format control metadata. A pre-START READ-buffer barrier now preserves that initial160B metadata, but both +150ms and zero-change RAW trials stop after two matching WR completions. The zero-change trial also observed the actual downstream STARTED state and a matching successful owner START containing the original connection-proxy subgraph. These results narrow the remaining relay issue; they establish neither sustained forwarding nor receiver playback. Each completed trial restored the verified normal baseline, original signed DSP and previous codec selection.
- The native English OneUI status view updates automatically and separates current DSP observations from history. R3 packet summaries provide ENC LEVEL and an encoder frame-budget bitrate estimate; this estimate is explicitly distinct from measured Bluetooth/radio throughput. The legacy HQ96/R2.1 path does not emit the same R3 ENC LEVEL record, so its raw rate/quality observations remain separate.
- The settings APK now has a normal launcher icon and can establish its bounded Root connection after the user grants KernelSU access. Action and the minimal KernelSU launcher remain optional. Actual normal-app foreground observation captured automatic changes between encoder levels4/3 and frame-budget estimates434.3/337.8kb/s; the refresh cadence is approximately one second. Each value also expires independently when status requests stall. Module removal still owns companion-app cleanup.
- Saving external HQ/LL delay requests is implemented. A new application transaction and native progress display are being connected, but lifecycle qualification remains disabled until continuous transfer and independently supervised recovery pass on the phone. Saved values, accepted INIT and a single completed transformed buffer cannot enable a production application capability.
- A packet TTP near190–202ms plus a requested100ms increment would be near290–302ms in that packet field. This is an internal timing target, not a measured phone-to-earbud delay. No approximately300ms receiver-delay setting has yet been verified.
