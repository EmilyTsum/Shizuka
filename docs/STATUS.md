# Status

- 0.8.1-test makes the DZIF Classic-active prerequisite respect Android's connection policy: a forbidden Classic profile does not prevent LE activation. The APK passes 12 helper and 2,592 active-gate cases; allowed/unknown policies retain the stock active-device checks. On-device LE activation and LC3 48 kHz/16-bit playback were observed, and the user confirmed LC3 playback. A Classic-forbidden trial also encountered LE CIS/ACL timeouts; the final heard session had A2DP and headset policies allowed. This is not a verified fix for every LE-only connection failure. Full kernel/DFRoot reboot remains untested.
- 0.8.0-test separates shared Android settings/status tools from the Samsung native/runtime backend. Per-device preferences follow Android; legacy connect-time codec replay is removed. Exact-input full builds, all 19 original host suites, ARM64 dispatch, configuration migration and real policy start/stop passed. Adaptive96 to Lossless44 received successful controller offload STARTs and normal two-earbud listening confirmation. A fresh Air6 Classic ACL matched a reference QHS-state1 PHY notification prefix; its extra trailing byte remains uninterpreted. Diagnostic event reporting was reset through rollback/reactivation. Native device support remains restricted to the exact DZIF inputs.

Current follow-ups: preserve playback when explicitly switching LE to Classic, and review the Samsung Call/Audio switches displaying OFF during LE use. These are not covered by the 0.8.1 listening confirmation.

- 0.7.2-test keeps Adaptive/Lossless on the DSP path when an unrelated LDAC/SSC preference remains enabled. The captured failure used software encoding despite a valid Adaptive/Lossless selection. The patched APK passed 486 executed predicate cases, six on-device codec selections and Developer Options Adaptive/Lossless changes with successful controller offload STARTs. A fresh Adaptive96→Lossless44 replay received successful controller STARTs, and the user confirmed normal audio in both Air6 Pro earbuds with Lossless selected. This does not establish that every switching failure is fixed.
- 0.7.1-test retains optional QHS enablement and fixes ordinary Android sh compatibility for lifecycle locks.
- aptX HD: fixed the LL offload trampoline replaying `cmp w8,#3` instead of the stock `#2`, which incorrectly routed HD into the unknown-codec branch and sent an empty controller START. The corrected build passes 40 stock/private ARM64 dispatch cases; BT-B10 now receives a valid HD START with controller status 0. BT-B10 HD indication and normal audio were confirmed by listening at 48 kHz/24-bit.
- BT-B10 also rejected some aptX-to-HD switches with AVDTP BAD_STATE while the old media L2CAP channel was still closing. Genuine HD SetConfiguration now uses the existing bounded teardown guard; private Adaptive proxy and unrelated codec paths are excluded. BT-B10 aptX→HD and HD→Adaptive→HD selections passed on-device; final HD audio and switching were confirmed by the user.
- aptX LL: playback, codec round trips, and 44.1↔48 kHz switching were listening-tested with Motion+. Absolute latency has not been measured.
- Adaptive: Air6 Pro 48 kHz/HQ passed listening tests. QHS-enabled 96 kHz/24-bit/HQ received actual DSP QHS1, ramped quality 3→4→5 without recorded reduction, and passed a short listening test. QHS-enabled 44.1 kHz Lossless also passed a short fixed-tone listening test; this does not establish a general fix for every periodic dropout.
- LE Audio: connection, display, and playback in both Air6 Pro earbuds were verified.
- QHS: the trusted opt-in now enables the two tested Hamilton NVM bits and the existing host-aware startup request. Input hashes, owned temporary mounts and post-reset local capabilities are checked; rollback restores the original file and controller response. Air6 Pro PHY notification and DSP QHS1 were observed; see [QHS.md](QHS.md).
- Lossless: the separate selection and 16-bit Android display retain required 24-bit DSP input. With QHS enabled, all 2,004 consecutive packet records in a steady 30-second capture remained in actual state12/STATE_ENCLEVEL_5_LOSSLESS. Receiver PCM bit-for-bit comparison was not performed.
- Logs showed ENCLEVEL 3↔4 transitions, but their causal relationship to dropouts is unconfirmed. Changing the resynchronization timer did not help.
- A physical click marker also occurred after about 46 seconds at unchanged ENCLEVEL 4, with consecutive encoder packet numbers around the marker. Level changes are not necessary for every reported click; encoded content, downstream timing and radio delivery are still unverified.
- The KernelSU WebUI shows Android's active media route and codec selection, independently of DSP observations. It does not enable DSP logging.
- Status snapshots were checked on-device for Adaptive 44.1 kHz/24-bit, Lossless selection 44.1 kHz/16-bit, and LE Audio LC3 48 kHz/16-bit. WebUI rendering and unavailable/stale-state behavior have host checks. See [44KHZ.md](44KHZ.md) for the investigation's measurements and limits.
- Ineffective experimental DSP timer, PCM width, and transport clock changes are excluded.
- Before the QHS addition, the reconfiguration repair was applied with exact APK/native/HAL hash checks. Its initial generation passed Adaptive96/HQ and 48/HQ after 44.1→48 and identical48 reapplication with Air6 Pro. The final HQ-default generation passed a fresh Adaptive48/24-bit/HQ listening check;96, LL, LE and full reboot were not retested on that final generation. Explicit runtime LL and build overrides remain available.
- Explicit Adaptive/Lossless retries now renew the private configuration revision, including unchanged requested values; default/startup vectors remain idempotent. Lossless also bypasses Java's unchanged-feeding early return. Controller START/STOP ownership and pending callbacks survive cancellation and failed STOP. These repairs are not a verified fix for the 44.1 kHz click or every intermittent silent change.
- Android's A2DP playback flag can clear after reconfiguration while the HAL still feeds audio and the user hears normal playback. It must not trigger automatic recovery or be presented as proof of silence.

Reports should include the commit, phone/firmware, receiver, codec/sample rate, and symptoms. Remove device identifiers before publishing raw logs.

The integrated QHS module passed on-device enable → rollback → re-enable checks: actual local controller features FC → CC → FC, with original NVM restored during rollback. The final integrated generation also accepted 96 kHz offload START; negotiated PHY was not separately sampled in that final generation. The DSP and listening evidence above was acquired with the same two-bit input in controlled trials. Full reboot reapplication remains untested. The 0.7.1 shell entry guard passed actual plain-sh FD7/FD8 checks while Bluetooth/audio PIDs remained unchanged.

Later listening was generally stable after a possible initial brief interruption. The marked replay maintained Lossless for 64.8 seconds and showed no encoder/QHS change near its single uncertain marker. A repeating 40-second fault is not established.
