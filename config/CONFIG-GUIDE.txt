Shizuka Bluetooth

Android owns per-device codec selection, sample rate, bit depth, transport and
profile permissions. Change these through Android Bluetooth Settings/Developer
Options, or use config.sh device ADDRESS|active for system-backed preferences.
The plugin does not retain a target address or replay codec defaults on connect.
Reconnect selection and persistence of detailed codec parameters follow Android.

Optional extension file: /data/adb/shizuka/config.conf
No configuration file is needed for default behavior. Configuration is key=value
data and is never executed as shell code. See config.example.conf (schema 2).

classic_qhs_host_aware=false: no controller overlay/request or resident policy.
aptx_voice_enabled=system: leave Android's property unchanged.
adaptive_priority=system: leave Android's priority property unchanged.
aptx_hd_priority=system: leave Android's priority property unchanged.
Explicit voice/priority property overrides are applied on module activation. Property recovery
restores only this activation's changes and preserves later user/system changes.

adaptive_hq_ttp_delta_ms=0: saved Adaptive/Lossless HQ TTP intent.
adaptive_ll_ttp_delta_ms=0: independent Adaptive LL TTP intent.
HQ accepts 0..150 ms and LL accepts 0..100 ms (step 1), default 0. The old aptx_hq_ttp_delta_ms
spelling is accepted on input; saves use adaptive_ names. Duplicate aliases fail.
config.sh tuning capabilities|get|set|plan provides versioned JSON. Capabilities
come from typed definitions and per-device providers. Adaptive LL playback was
already supported; these controls add TTP tuning. Separate aptX LL tuning and
independent HQ Adaptive/Lossless increments have no provider yet.
Saving or KernelSU Action does not apply DSP tuning. Generate a verified offline
candidate, then measure a fresh DSP graph. See docs/CONTROLS.md in the repo.

Opt-in diagnostics.sh capture SECONDS (5..120) exports stock DSP observations.
diagnostics.sh list / export SESSION / recover manages private session files.
Capture is not started by status refresh or at boot. Its device path is untested.

QHS requires the verified Samsung DZIF backend, a trusted root-owned regular
configuration file, Bluetooth ON, exact controller firmware and a module
reactivation. Peer support and radio conditions determine actual QHS/Lossless.
Controller acceptance or Android's Lossless selection is not bit-perfect proof.

Legacy /data/adb/s25_bluetooth/config.conf remains readable for extension controls.
Its per-device preferences are ignored; legacy forced defaults inherit Android.
config.sh migrate writes only the minimal extension file in the new location.
The old file is preserved. Failed/invalid canonical files do not fall back to it.

KernelSU Action starts an unverified archive as a 15-minute rollback trial.
Manual restore:
  su -c 'sh /data/adb/modules/s25_aptx_adaptive/control.sh rollback'
Native activation supports only the exact stock hashes of the selected backend.
